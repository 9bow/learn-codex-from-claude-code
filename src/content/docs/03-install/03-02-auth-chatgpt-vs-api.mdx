Codex는 ChatGPT 계정으로 로그인하거나 OpenAI API 키로 인증할 수 있습니다. 둘은 단순히 로그인 화면이 다른 것이 아니라, 사용 한도·청구·조직 정책·일부 연결 기능의 가용성이 달라질 수 있는 경로입니다.

## ChatGPT 계정으로 로그인

처음 `codex`를 실행하면 ChatGPT 로그인 또는 현재 환경에서 제공되는 다른 로그인 방식을 선택합니다. ChatGPT 플랜으로 Codex를 사용할 때는 계정의 사용 한도와 워크스페이스 정책이 적용됩니다.

```bash
codex
```

ChatGPT 데스크톱 앱, ChatGPT Work, 예약 작업처럼 ChatGPT 제품 표면과 연결된 기능을 쓸 때는 해당 제품의 로그인과 권한 정책을 확인합니다. 조직 계정에서는 관리자가 허용한 모델, 플러그인, 외부 연결만 보일 수 있습니다.

## API 키로 인증

API 키는 자동화, CI, SDK 기반 통합처럼 사용량을 API 프로젝트로 관리해야 하는 상황에 적합합니다. 키는 환경 변수나 CI의 secret store에 저장하고, 저장소나 문서에 직접 적지 않습니다.

```bash
export OPENAI_API_KEY="<your-api-key>"
codex
```

CLI에서 지원하는 로그인 흐름과 키 저장 방식은 버전에 따라 달라질 수 있으므로 `codex login --help`로 확인합니다. CI에서는 사람이 쓰는 개인 토큰을 재사용하지 말고, 해당 프로젝트의 최소 권한 secret를 사용합니다.

```text
개인 로컬 탐색 · ChatGPT 데스크톱 앱
             │
             ▼
       ChatGPT 로그인 검토

CI · SDK · 사용량을 API 프로젝트로 분리
             │
             ▼
          API 키 인증 검토
```

## 무엇이 달라지는가

| 판단 기준 | ChatGPT 로그인 | API 키 인증 |
| --- | --- | --- |
| 사용 한도·청구 | ChatGPT 플랜과 워크스페이스 정책 | API 프로젝트의 사용량·한도 |
| 로컬 CLI·IDE | 지원 범위에서 사용 | 지원 범위에서 사용 |
| CI와 비대화형 실행 | 조직 정책을 먼저 확인 | secret 기반 자동화에 적합 |
| Cloud·플러그인·연결 기능 | 제품·플랜·관리자 정책에 따름 | 지원되는 기능과 OAuth 제약을 각각 확인 |
| 모델 가용성 | 계정·플랜·클라이언트에 따름 | API 프로젝트 권한과 모델 정책에 따름 |

:::caution[고정 기능표를 피한다]
"이 인증이면 항상 이 모델/Cloud/플러그인을 쓸 수 있다"는 표는 유지하기 어렵습니다. 공식 Plugins 문서도 API 키 인증에서 일부 OpenAI-curated plugin을 지원하지만, OAuth가 필요한 plugin은 제한될 수 있다고 설명합니다. 기능을 도입하기 직전에 현재 제품 표면과 연결 요구 사항을 확인하세요.
:::

## 핵심 정리

- ChatGPT 로그인과 API 키 인증은 사용 한도, 청구, 제품 기능의 경계가 다릅니다.
- API 키는 CI·SDK·자동화에, ChatGPT 로그인은 ChatGPT 제품 표면을 쓰는 작업에 우선 검토합니다.
- 모델, Cloud, plugin의 가용성을 인증 방식 하나로 단정하지 않고 현재 공식 문서와 계정 화면에서 확인합니다.
- 자격 증명은 저장소·문서·로그에서 제외하고 최소 권한으로 관리합니다.
