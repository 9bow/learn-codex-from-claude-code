## Action의 역할

`openai/codex-action@v1`은 GitHub Actions workflow에서 Codex를 실행하는 공식 Action입니다. Action은 Codex CLI를 설치하고, API 키를 제공하면 Responses API proxy를 시작한 뒤 지정한 권한으로 `codex exec`를 실행합니다. PR 리뷰, 릴리스 준비, 반복 품질 점검처럼 workflow로 재현할 수 있는 작업에 적합합니다.

Action은 사람이 하는 코드 리뷰를 없애는 도구가 아닙니다. 생성된 요약과 제안은 검토 입력이며, 권한이 있는 변경·게시·머지는 일반 CI와 마찬가지로 별도 보호 규칙을 따라야 합니다.

```text
GitHub event
    │
    ▼
checkout ── 최소 권한 workflow ── codex-action@v1
                                      │
                                      ▼
                           codex exec 결과·로그
                                      │
                                      ▼
                         사람 검토 · PR 보호 규칙
```

## 최소 권한 예시

다음은 변경을 쓰지 않는 PR 검토의 출발점입니다. 실제 secret 이름, 이벤트, 권한은 저장소 정책에 맞춰 조정합니다.

```yaml
name: Codex pull request review

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
        with:
          persist-credentials: false
      - uses: openai/codex-action@v1
        with:
          openai-api-key: ${{ secrets.OPENAI_API_KEY }}
          prompt: "변경된 코드에서 재현 가능한 문제만 우선순위와 근거를 붙여 보고해줘."
```

공식 문서는 Action이 Linux와 macOS runner에서 실행된다고 설명합니다. Windows runner에서는 안전 전략을 별도로 설정해야 하므로, 기존 CI가 Windows라면 먼저 공식 Action 문서의 지원 조건을 확인합니다.

## 운영 원칙

| 원칙 | 적용 방법 |
| --- | --- |
| secret 최소화 | API 키는 GitHub secret에만 저장하고 출력하지 않습니다. |
| 권한 최소화 | 읽기 전용 검토에는 `contents: read`로 시작합니다. |
| 입력 신뢰 | PR 본문·코드·이슈의 지시를 신뢰할 수 없는 입력으로 다룹니다. |
| 결과 검토 | 리뷰 결과를 자동 머지·배포의 근거로 단독 사용하지 않습니다. |
| 재현성 | prompt를 workflow 파일 또는 버전 관리된 prompt 파일에 둡니다. |

<ConceptCard title="먼저 읽기 전용으로 시작한다">
처음 도입할 때는 수정·댓글 작성·외부 배포를 시키지 말고, 읽기 전용 분석과 사람이 확인하는 보고서부터 시작합니다. 결과가 안정적이고 팀의 검토 기준이 합의된 뒤에만 필요한 범위의 후속 권한을 추가합니다.
</ConceptCard>

## 핵심 정리

- `openai/codex-action@v1`은 workflow 안에서 `codex exec`를 재현 가능하게 실행합니다.
- PR 리뷰와 품질 점검에 적합하지만, 사람의 최종 검토와 GitHub 보호 규칙을 대체하지 않습니다.
- API 키·workflow 권한·이벤트 입력을 최소화하고 로그 유출을 막습니다.
