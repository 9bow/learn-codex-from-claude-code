## Profiles란

Profile은 기본 사용자 설정 위에 덧씌우는 별도 설정 파일입니다. 현재 Codex는 `--profile <name>`으로 `$CODEX_HOME/<name>.config.toml` 파일을 선택합니다. 예를 들어 평소 설정은 `config.toml`에 두고, 읽기 전용 리뷰나 특정 모델을 쓰는 작업만 profile로 분리할 수 있습니다.

프로필은 저장소의 공통 정책을 대체하지 않습니다. `.codex/config.toml`은 신뢰한 프로젝트에만 로드되는 프로젝트 범위 설정이고, provider·인증·profile 선택 같은 일부 키는 프로젝트 설정에서 무시됩니다. 개인 기본값과 팀 공통 규칙의 책임을 섞지 않는 것이 중요합니다.

```text
사용자 config.toml
       │
       ├── deep-review.config.toml  (--profile deep-review)
       └── focused.config.toml      (--profile focused)
                    │
                    ▼
      신뢰한 프로젝트의 .codex/config.toml
                    │
                    ▼
           현재 작업의 승인·sandbox 정책
```

## profile 파일 만들기

아래 예시는 리뷰 전용 profile입니다. 모델 이름은 예시일 뿐이며, 실제로 선택 가능한 모델과 추론 수준은 현재 계정의 Codex 모델 선택기에서 확인해야 합니다.

```toml
# $CODEX_HOME/deep-review.config.toml

model = "gpt-5.6-sol"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "read-only"
```

기본 설정은 `$CODEX_HOME/config.toml`에 둘 수 있습니다.

```toml
# $CODEX_HOME/config.toml

model_reasoning_effort = "medium"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

`$CODEX_HOME`은 Codex가 설정을 보관하는 디렉터리입니다. 운영체제나 설치 방식에 따라 실제 경로가 다를 수 있으므로, 경로를 하드코딩한 팀 문서보다 `codex --help`와 공식 설정 문서를 우선합니다.

## profile 선택하기

```bash
# 읽기 전용 심층 리뷰
codex --profile deep-review "현재 브랜치의 변경을 검토해줘"

# 기본 사용자 설정
codex "테스트 실패 원인을 찾아줘"
```

profile은 편의 기능이지 보안 경계가 아닙니다. 실행 전에 `/permissions` 또는 현재 세션 상태를 확인하고, 외부 서비스나 비밀값이 필요한 작업은 별도 승인을 남깁니다.

| 상황 | 권장 설정 방향 | 확인할 것 |
| --- | --- | --- |
| 코드 검토 | `read-only`, 필요 시 높은 추론 수준 | diff 범위와 리뷰 기준 |
| 작은 로컬 수정 | `workspace-write` | 테스트 명령과 변경 파일 |
| CI/자동화 | 비대화형 실행과 최소 권한 | 비밀값, runner, 로그 보존 |
| 팀 공통 규칙 | 프로젝트 `AGENTS.md`와 `.codex/config.toml` | 신뢰된 저장소인지 여부 |

## 핵심 정리

- 현재 profile은 `[profiles.<name>]` 블록이 아니라 `$CODEX_HOME/<name>.config.toml` 파일로 관리합니다.
- `--profile <name>`은 기본 사용자 설정 위에 해당 파일을 적용합니다.
- 프로젝트 `.codex/config.toml`은 별도 계층이며, 인증·provider·profile 선택 키를 대체할 수 없습니다.
- 모델, 추론 수준, 권한은 계정과 환경에 따라 달라질 수 있으므로 실행 전에 확인합니다.
