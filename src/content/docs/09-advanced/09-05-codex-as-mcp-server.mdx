## Codex를 MCP 서버로 노출

`codex mcp-server` 명령은 Codex 자체를 **MCP(Model Context Protocol) 서버**로 노출합니다. 다른 MCP 클라이언트는 이를 통해 Codex 세션을 시작하거나 같은 스레드에 후속 지시를 보낼 수 있습니다. 현재 공식 문서의 기본 전송 방식은 표준 입출력(stdio)입니다.

```bash
# Codex를 MCP 서버로 시작 (stdio 트랜스포트)
codex mcp-server

```

서버를 시작한 MCP 클라이언트는 `tools/list`로 제공 도구를 확인해야 합니다. 공식 문서 기준으로 새 Codex 대화를 시작하는 `codex`와 기존 대화를 잇는 `codex-reply` 도구가 제공됩니다.

```text
┌─────────────┐    stdio MCP    ┌──────────────────┐
│ MCP 클라이언트 │ ────────────▶ │ codex mcp-server │
└──────┬──────┘                 └────────┬─────────┘
       │ tools/call                     │ Codex 세션
       └─────────────────────────────────┘
```

## MCP 클라이언트에서 Codex 호출하기

안전한 활용 패턴은 **오케스트레이터(MCP 클라이언트)가 Codex(MCP 서버)를 호출**하고, 작업 범위·권한·작업 디렉터리·검증 절차를 명시하는 구조입니다. 공식 예제는 OpenAI Agents SDK의 stdio MCP 클라이언트를 사용합니다. 다른 MCP 클라이언트도 연결할 수 있지만, 각 제품의 MCP 설정 형식과 승인 흐름을 먼저 확인해야 합니다.

**1단계: MCP 서버 등록**

MCP 클라이언트에 `codex mcp-server`를 stdio 명령으로 등록합니다. 아래는 설정 구조를 설명하는 예시이며, 실제 키 이름은 사용하는 MCP 클라이언트의 문서를 따릅니다.

```json
{
  "mcpServers": {
    "codex": {
      "command": "codex",
      "args": ["mcp-server"],
      "env": {
        "OPENAI_API_KEY": "${OPENAI_API_KEY}"
      }
    }
  }
}
```

**2단계: Codex 도구 호출**

등록 후에는 새 세션용 `codex` 도구에 프롬프트·작업 디렉터리·샌드박스·승인 정책을 명시해 호출합니다. 이전 세션을 잇는 경우에는 반환된 `threadId`를 `codex-reply`에 전달합니다.

```
"codex 도구를 read-only 샌드박스와 현재 저장소 경로로 호출해
src/api.ts의 성능 병목을 근거와 함께 분석해 줘"
```

<ConceptCard title="agent-to-agent 워크플로 예시">
다음은 계획 역할과 구현 역할을 분리하는 패턴입니다.

1. **오케스트레이터** : 아키텍처 분석, 리팩터링 계획 수립
2. **Codex (MCP 서버로 호출)** : 계획에 따른 코드 변경 실행
3. **검토 단계** : 변경된 코드 검토, 테스트 결과 확인, 추가 지시

이 패턴은 역할을 분명히 하며, 구현 권한과 검증 책임을 작업 단계별로 분리합니다.
</ConceptCard>

## Codex에서 다른 MCP 서버 사용

반대 방향도 가능합니다. Codex가 MCP 클라이언트가 되어 외부 MCP 서버를 호출하는 구성입니다. `config.toml`에 MCP 서버를 등록하면 됩니다.

```toml
# ~/.codex/config.toml

[mcp_servers.github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_TOKEN = "${GITHUB_TOKEN}" }

[mcp_servers.filesystem]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/tmp/workspace"]
enabled = true
```

  - MCP 클라이언트가 Codex 세션 시작·후속 대화 도구를 호출 가능
  - `codex plugin marketplace` 로 MCP 기반 플러그인 검색 가능

## 핵심 정리

- `codex mcp-server` 명령으로 Codex를 MCP 서버로 노출할 수 있습니다
- 다른 MCP 클라이언트가 Codex를 도구로 호출할 수 있으며, 각 클라이언트의 등록 형식은 해당 문서를 따릅니다
- 공식 예제는 OpenAI Agents SDK에서 stdio MCP 서버로 Codex를 연결합니다
- 반대로 Codex가 `config.toml`의 `[mcp_servers]` 로 외부 MCP 서버를 클라이언트로 호출할 수도 있습니다
- 새 대화에는 `codex`, 후속 대화에는 반환된 `threadId`를 사용하는 `codex-reply` 도구를 사용합니다
- `approval-policy`, `sandbox`, `cwd`를 명시하고 실행 결과와 테스트를 독립적으로 검토합니다
