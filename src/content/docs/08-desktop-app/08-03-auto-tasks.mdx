## 예약 작업이란

예약 작업(scheduled task)은 일정에 따라 백그라운드에서 반복 실행하는 작업입니다. 실행 상태와 최근 결과는 Scheduled에서 확인합니다. 반복할 프롬프트가 독립적이면 standalone 예약 작업을, 같은 대화의 결정과 맥락을 이어야 하면 채팅 안의 예약 작업을 선택합니다.

```text
안정된 수동 절차
      │
      ▼
입력 · 결과 형식 · 실패 시 알림 · 승인 지점 정의
      │
      ▼
standalone 작업 ────── 채팅 안의 작업
매번 저장된 프롬프트    같은 대화 맥락 유지
      │                      │
      └────── Scheduled에서 상태·결과 검토 ──────┘
```

## 실행 환경을 구분한다

ChatGPT 데스크톱 앱의 예약 작업은 로컬 프로젝트를 프로젝트 디렉터리 또는 격리된 Git worktree에서 다룰 수 있습니다. 이때 컴퓨터와 앱이 실행 중이어야 로컬 파일에 접근할 수 있습니다. Git 저장소에서는 전용 background worktree를 써서 현재 작업과 충돌을 줄일 수 있습니다.

웹의 예약 작업은 업로드한 자료, 연결된 도구, skill, plugin을 쓸 수 있지만 컴퓨터의 폴더나 worktree를 계속 보관하지 않습니다. Codex CLI와 IDE extension은 예약 작업을 만드는 관리 화면을 제공하지 않으므로, 프롬프트·skill·스크립트를 준비하고 테스트하는 역할에 적합합니다.

## 예약하기 좋은 업무

수동으로 여러 번 성공했고 산출물을 사람이 검토할 수 있는 절차만 예약합니다.

| 업무 | 좋은 완료 기준 |
| --- | --- |
| 주간 변경 요약 | 링크와 근거를 포함한 Markdown 요약 |
| 실패한 CI 점검 | 실패 workflow, 재현 근거, 다음 조치 목록 |
| 오래된 문서 점검 | 변경 후보와 공식 출처 목록, 자동 수정 없음 |
| 팀 회고 초안 | 지난 결과를 사실과 의견으로 구분한 초안 |

<ConceptCard title="불안정한 절차를 먼저 자동화하지 않는다">
외부 시스템에 게시하거나 파일을 바꾸는 절차는 먼저 수동으로 안정화합니다. 입력 데이터, 필요한 plugin 권한, 파일 쓰기 범위, 실패 시 알림, 사람이 최종 승인할 지점을 분명히 한 뒤 예약합니다. 예약 작업의 결과는 자동으로 옳다고 가정하지 않고 매 실행을 검토합니다.
</ConceptCard>

## 핵심 정리

- 예약 작업은 standalone 또는 기존 채팅의 맥락을 이어 가는 방식으로 만들 수 있습니다.
- 로컬 프로젝트 예약 작업은 데스크톱 앱과 실행 중인 로컬 환경이 필요하며 worktree를 사용할 수 있습니다.
- 웹 예약 작업은 연결된 도구와 업로드 자료를 쓸 수 있지만 로컬 폴더를 지속적으로 보관하지 않습니다.
- 반복 실행 전에는 수동 성공, 최소 권한, 실패 알림, 사람 검토 기준을 마련합니다.
