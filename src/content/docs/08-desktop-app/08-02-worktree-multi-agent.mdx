## 멀티 에이전트의 충돌 문제

여러 에이전트가 같은 파일을 동시에 수정하면 어떻게 될까요? 에이전트 A가 `auth/session.ts` 를 리팩터링하는 동안 에이전트 B가 같은 파일에 새 기능을 추가하면 두 변경이 충돌합니다.

일반적인 git 워크플로에서는 브랜치를 나눠 작업한 뒤 머지 시 충돌을 해결합니다. 하지만 에이전트가 같은 워킹 트리를 공유하면 브랜치를 만들기도 전에 파일 수준 충돌이 발생합니다.

Codex Desktop App에서는 워크트리를 사용해 작업을 격리할 수 있습니다. 같은 Git 저장소에서 병렬 대화를 운영하되, 어떤 대화를 로컬 체크아웃에서 실행하고 어떤 대화를 워크트리로 보낼지는 작업 성격에 맞춰 선택합니다.

## 워크트리 작동 원리

Codex 관리 워크트리는 표준 `git worktree` 위에서 동작합니다. Git 저장소에서 워크트리로 시작한 대화는 별도 체크아웃에서 실행되며, 로컬에서 진행하던 대화는 **Handoff**로 워크트리로 옮길 수 있습니다. 예약 작업은 진행 중인 로컬 작업과 충돌하지 않도록 전용 백그라운드 워크트리에서 실행될 수 있습니다.

```
.git/
  worktrees/
    <managed-worktree-a>/   ← 대화 A용 체크아웃
    <managed-worktree-b>/   ← 대화 B용 체크아웃
```

각 워크트리는 파일 체크아웃을 따로 가지지만 Git 메타데이터를 공유합니다. 따라서 서로 다른 작업을 분리할 수 있지만, 같은 브랜치를 두 워크트리에서 동시에 체크아웃할 수는 없습니다.

```text
┌───────────────┐   Handoff   ┌────────────────────┐
│ Local checkout │ ─────────▶ │ Codex-managed worktree │
└───────────────┘             └─────────┬──────────┘
                                        │
                              ┌─────────▼──────────┐
                              │ diff·테스트 검토 후 Local │
                              └────────────────────┘
```

## 로컬 git에 영향 없음

워크트리에서 실행 중인 대화의 수정은 로컬 체크아웃의 `git status`에 바로 나타나지 않습니다. 다만 로컬에서 시작한 대화는 로컬 작업 트리를 직접 수정하므로, 모든 대화가 자동으로 격리된다고 가정하면 안 됩니다.

에이전트 작업이 완료된 후 diff를 검토하고 원하는 변경만 머지하거나 적용할 수 있습니다.

```bash
# 로컬 워킹 트리는 깨끗한 상태
git status
# → nothing to commit, working tree clean

# Desktop App에서 에이전트 작업 완료 후
# diff 검토 → 승인 → 로컬에 적용
```

:::tip[팁]
Desktop App의 diff 검토 화면에서 변경 사항을 확인하고 "에디터에서 열기" 버튼으로 VS Code나 원하는 에디터에서 바로 열 수 있습니다. 검토 후 코멘트를 달고 부분 적용도 가능합니다.
:::

## CLI git-worktree와의 관계

Desktop App의 워크트리 기능은 표준 `git worktree` 위에서 동작합니다. CLI에서 직접 worktree를 관리할 수도 있습니다.

```bash
# 수동으로 worktree 생성
git worktree add ../feature-branch feature/new-auth

# Codex CLI를 특정 worktree에서 실행
cd ../feature-branch
codex "인증 모듈을 OAuth 2.0으로 업그레이드해 줘"
```

Desktop App은 Codex 관리 워크트리를 만들고 정리할 수 있습니다. 장기 작업이 필요하면 프로젝트 메뉴에서 영구 워크트리를 만들 수 있으며, 일반 관리 워크트리는 가볍고 일회성 작업에 적합합니다.

1. **에이전트 A**: `feature/payments` 브랜치에서 결제 모듈 구현

세 에이전트가 같은 리포를 대상으로 동시에 작업하지만, 각자 격리된 워크트리에서 실행되므로 충돌이 없습니다. Desktop App 화면에서 세 에이전트의 진행 상황을 한눈에 확인하고 diff를 순서대로 검토할 수 있습니다.

## 핵심 정리

- Desktop App에서는 대화를 **로컬 또는 워크트리**에서 실행하도록 선택할 수 있습니다
- 워크트리 대화의 변경은 로컬 체크아웃과 분리되지만, 로컬 대화는 로컬 파일을 직접 수정합니다
- 내부적으로 표준 `git worktree`를 사용하며, CLI에서도 수동으로 관리할 수 있습니다
- Handoff로 대화를 로컬과 워크트리 사이에서 안전하게 이동할 수 있습니다
- 영구 워크트리는 장기 환경에, Codex 관리 워크트리는 가볍고 분리된 작업에 적합합니다
- 동일 리포에서 여러 에이전트를 동시에 실행해 **병렬 개발 속도** 를 높일 수 있습니다
