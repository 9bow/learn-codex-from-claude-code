## /goal은 무엇인가

`/goal`은 여러 단계가 필요한 작업을 하나의 **목표(objective)** 와 완료 기준으로 묶는 흐름입니다. 목표를 시작하면 Codex는 같은 스레드의 제약과 진행 상태를 참고하며 다음 작업을 선택합니다. 현재 공식 문서는 ChatGPT 데스크톱 앱, Codex CLI, IDE 확장에서 `/goal`을 사용할 수 있다고 안내합니다.

이 기능은 "계속 실행해"라는 막연한 지시를 대체하지 않습니다. 성공 조건, 검증 명령, 사람이 결정해야 할 경계를 먼저 적어 두어야 합니다. 목표가 명확할수록 중간에 작업이 커지거나 엉뚱한 방향으로 확장될 위험이 줄어듭니다.

```text
요청과 제약
    │
    ▼
/plan ── 요구사항과 선택지 정리
    │  완료 기준이 명확한가?
    ▼
/goal ── 구현 · 검증 · 상태 보고
    │
    ▼
사용자 검토 ── 완료 / 후속 목표 / 중단
```

<ConceptCard title="/plan과 /goal의 역할">
`/plan`은 아직 결정을 내려야 하는 문제를 조사하고, 제약과 선택지를 정리하는 데 적합합니다. `/goal`은 결과와 확인 방법이 이미 합의된 작업을 이어 가는 데 적합합니다. 요구사항이 모호하면 `/plan`부터 시작하고, 목표가 검증 가능해진 뒤 `/goal`로 옮깁니다.
</ConceptCard>

## 현재 가용성 확인

기능의 가용성은 설치한 Codex 버전, 사용 표면, 계정 정책에 따라 달라질 수 있습니다. 우선 현재 버전과 기능 상태를 확인합니다.

```bash
codex --version
codex features list
```

2026-08-28에 확인한 Codex CLI 0.148.0에서는 `goals`가 stable로 표시됩니다. 과거의 "별도 feature flag를 켜야 한다"는 안내는 현재 설치에 그대로 적용하면 안 됩니다. 팀 문서에는 특정 버전의 출력값을 고정하기보다 위 명령과 공식 Feature Maturity 문서를 확인하도록 남기는 편이 안전합니다.

## 좋은 목표의 형태

좋은 목표는 원하는 결과만 말하지 않고, Codex가 멈출 기준을 제공합니다.

```text
/goal 인증 모듈의 refresh token 경쟁 조건을 재현하는 테스트를 추가하고 수정해줘.
범위: src/auth와 해당 테스트만 변경.
완료 기준: 새 회귀 테스트가 실패를 재현한 뒤 통과하고, pnpm test auth가 성공할 것.
제약: 의존성 추가와 인증 정보 변경은 하지 말 것.
```

| 포함할 정보 | 이유 |
| --- | --- |
| 결과와 파일 범위 | 관련 없는 리팩터링을 막습니다. |
| 완료 기준 | Codex와 사용자가 같은 종료 조건을 공유합니다. |
| 검증 명령 | 구현 뒤 실제로 확인할 수 있습니다. |
| 제약과 승인 지점 | 배포, 비밀값, 데이터 변경 같은 위험을 분리합니다. |

반대로 "앱을 전반적으로 개선해줘"는 목표로 적합하지 않습니다. 무엇을 바꿀지와 언제 멈출지가 없으므로, 우선 `/plan`으로 범위를 정하거나 작은 목표 여러 개로 나눕니다.

## 진행 중인 목표 다루기

목표를 시작한 뒤에는 같은 스레드에서 제약을 추가하거나 상태를 물을 수 있습니다. 방향이 바뀌면 이전 목표를 완료로 처리했다고 가정하지 말고, 무엇을 유지하고 무엇을 버릴지 명시합니다. 독립적인 작업은 별도 스레드나 하위 에이전트로 나누는 편이 컨텍스트를 덜 섞습니다.

목표가 예상보다 커졌다면 다음 순서가 안전합니다.

1. 현재 diff와 검증 결과를 요약하게 합니다.
2. 남은 일을 검증 가능한 작은 목표로 다시 나눕니다.
3. 변경 권한이나 외부 시스템 접근이 필요해지면 사용자 승인을 받습니다.

## /goal을 쓰지 않는 편이 나은 경우

- 요구사항, 기술 선택, 성공 기준이 아직 불명확할 때
- 프로덕션 데이터 삭제, 배포, 결제처럼 별도 승인과 수동 검토가 필요한 때
- 독립적인 여러 작업이 같은 파일을 동시에 바꿀 가능성이 있을 때
- 테스트나 관찰 가능한 완료 기준이 전혀 없을 때

이 경우에는 일반 대화나 `/plan`으로 충분히 좁힌 뒤 목표를 시작합니다. `/goal`은 자율성을 늘리는 명령이 아니라, 긴 작업의 완료 조건을 명확하게 관리하는 도구입니다.

## 핵심 정리

- `/goal`은 장기 작업의 목표와 완료 기준을 같은 스레드에서 관리합니다.
- 현재 가용성은 `codex --version`, `codex features list`, 공식 Feature Maturity 문서로 확인합니다.
- 먼저 `/plan`으로 불확실성을 줄이고, 범위·검증·중단 조건이 정해진 뒤 사용합니다.
- 목표가 커지거나 위험한 권한이 필요해지면 요약 후 분할하고 사용자 검토로 돌아갑니다.
